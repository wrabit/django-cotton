Components are reusable pieces of view template. They can contain native Django template syntax and can be used inside standard Django templates.

1. The basic building block: {% verbatim %}{{ slot }}{% endverbatim %}

The {% verbatim %}{{ slot }}{% endverbatim %} variable captures all content passed between a component's opening and closing tags.

{% cotton:verbatim %}{% verbatim %}
{{ slot }}
{% endverbatim %}{% endcotton:verbatim %}

Used in a parent template:

{% cotton:verbatim %}{% verbatim %}

Some content

 {% endverbatim %}{% endcotton:verbatim %}
Some content

We can further customize components with attribute, which allow you to pass specific data into the component as key-value pairs.

{% cotton:verbatim %}{% verbatim %}

It's {{ temperature }}o{{ unit }} and the condition is {{ condition }}.

{% endcotton:verbatim %}{% endverbatim %} {% cotton:verbatim %}{% verbatim %} {% endcotton:verbatim %}{% endverbatim %} It's 23oC and the condition is windy.

If we want to pass HTML instead of just a string (or another data type) into a component, we can pass them as named slots with the {{ '...'|force_escape }} syntax.

So as with normal attributes, you reference the slot content like normal variables, as in:

{% cotton:verbatim %}{% verbatim %}

{{ day }}:

{{ icon }} {{ label }}
{% endcotton:verbatim %}{% endverbatim %} {% cotton:verbatim %}{% verbatim %}
Sunny
 {% endcotton:verbatim %}{% endverbatim %}

Tuesday:

Sunny

By default, every attribute you pass to a component arrives as a string. To pass anything else, a variable from context, a boolean, a number, a list or a dict, prefix the attribute name with a colon.

{% cotton:verbatim %}{% verbatim %} {% endcotton:verbatim %}{% endverbatim %} {% cotton:verbatim %}{% verbatim %}

It's {{ today.temperature }}o{{ today.unit }} and the condition is {{ today.condition }}.

{% endcotton:verbatim %}{% endverbatim %}

Passing variables vs strings

:today="today" and today="{% verbatim %}{{ today }}{% endverbatim %}" do different things. The colon form hands the variable itself to the component, so it can read today.temperature. The template expression form renders in place first, so the component receives a string. Reach for the colon when the component needs the variable, and a template expression when you want a string, whether passed as is or built up.

{% cotton:verbatim %}{% verbatim %} {# today is the Weather object #} {# unit is the string "c" #} {# icon is the string "fa-sun" #} {% endverbatim %}{% endcotton:verbatim %} Note: variables can also be passed Django-style, today=today.

Python literals

The colon form evaluates Python literals, so numbers, booleans, None, lists and dicts can be written straight into the template.

{% cotton:verbatim %}{% verbatim %} {# prop == 1 #} {% endverbatim %}{% endcotton:verbatim %} {% cotton:verbatim %}{% verbatim %} {# enabled is True, prop is None #} {% endverbatim %}{% endcotton:verbatim %} {% cotton:verbatim %} {% verbatim %}{# for item in items #} {% endverbatim %}{% endcotton:verbatim %} {% cotton:verbatim %} {% verbatim %}{# mydict.name, mydict.products #} {% endverbatim %}{% endcotton:verbatim %} {% cotton:verbatim %}{% verbatim %} {# for image in slides #} {% endverbatim %}{% endcotton:verbatim %} {% cotton:verbatim %}{% verbatim %} {# is_highlighted is True when important #} {% endverbatim %}{% endcotton:verbatim %}

A typical use is a select component that takes its options from the parent:

Are carrots tasty?

5. Working with {% verbatim %}{{ attrs }}{% endverbatim %}

Every attribute passed to a component is collected into attrs, a dictionary the component can print, add to, pass on or trim. The simplest use is to reflect everything onto an element, which is what makes form inputs practical.

{% cotton:verbatim %}{% verbatim %} {% endcotton:verbatim %}{% endverbatim %}
{% cotton:verbatim %}{% verbatim %} {% endcotton:verbatim %}{% endverbatim %}

The next two sections cover the other things you can do with that dictionary: add to it from the outside, and take keys out of it from the inside. Both operate on the same attrs.

Pass a dictionary through the special :attrs attribute and its keys are merged into attrs alongside anything passed directly. Useful when a view, or another component, already holds the attributes you want applied.

{% cotton:verbatim %}{% verbatim %} {% endcotton:verbatim %}{% endverbatim %} {% cotton:verbatim %}{% verbatim %} def form_view(request): return render(request, "form_view.html", { "widget_attrs": { "placeholder": "Enter your name", "data-validate": "true", "size": "40", } }) {% endverbatim %}{% endcotton:verbatim %} {% cotton:verbatim %}{% verbatim %} {% endcotton:verbatim %}{% endverbatim %}

Passing attrs on to another component

Because attrs is just a dictionary, a wrapper component can hand the whole thing to the component it wraps, without naming each attribute.

{% cotton:verbatim %}{% verbatim %} {{ slot }} {% endcotton:verbatim %}{% endverbatim %}

See attribute proxying for the full pattern.

Some attributes are for the component to use, not for its HTML. Declare those in a single {{ ''|force_escape }} at the top of the component. A declared key is removed from attrs and becomes an ordinary template variable, with a default if you give one.

Defaults

Set a value in {{ ''|force_escape }} and it applies whenever the parent does not pass that attribute.

{{ slot }}

Keeping configuration out of {% verbatim %}{{ attrs }}{% endverbatim %}

Declaring a key with no value claims it without setting a default. Here label and errors are claimed, so they never reach the input, while placeholder is not, so it does.

{% cotton:verbatim %}{% verbatim %} {% if errors %} {% for error in errors %} {{ error }} {% endfor %} {% endif %} {% endcotton:verbatim %}{% endverbatim %} {% cotton:verbatim %}{% verbatim %} {% endcotton:verbatim %}{% endverbatim %}

Merging classes

A plain default is replaced when the parent passes the attribute. For class you usually want to add to it instead, so the component keeps its own classes and the parent can tweak the layout. Add :merge to the key and the parent's classes are appended to the default.

{% cotton:verbatim %}{% verbatim %} {% endcotton:verbatim %}{% endverbatim %} {% cotton:verbatim %}{% verbatim %} Save Save {% endcotton:verbatim %}{% endverbatim %}

A dynamic :class from the parent is merged the same way. Only class can be merged for now. The classes are joined as they are, so conflicting utility classes (say bg-red-500 from the parent and bg-blue-500 in the default) are both kept and the stylesheet decides which one wins.

Sometimes you just want to pass a simple boolean to a component. Cotton supports providing the attribute name without a value which will provide a boolean True to the component.

{% cotton:verbatim %}{% verbatim %} {% if required is True %} * {% endif %} {% endcotton:verbatim %}{% endverbatim %} {% cotton:verbatim %}{% verbatim %} {% endcotton:verbatim %}{% endverbatim %} *

By default, components inherit the parent template's full context. There are two ways to opt out:

only: total isolation per component

Add the only attribute to an individual component to block all outside context. The component sees nothing except its directly passed attributes: no parent template variables, no context processors (no request, no user, etc).

COTTON_ISOLATE_BY_DEFAULT: smart isolation project-wide

Set COTTON_ISOLATE_BY_DEFAULT = True in settings.py to make every component silently scoped: parent template variables (from {% verbatim %}{% with %}{% endverbatim %}, {% verbatim %}{% for %}{% endverbatim %}, the view context, etc.) do not leak in, but global context-processor output is preserved. Useful when you want isolation as the default but still want components to see request, user, messages, etc.

You can still add only on a per-component basis to also block context-processor output. See configuration.

The following key features allow you to build re-usable components with alpine.js:

  • x-data is accessible as {% verbatim %}{{ x_data }}{% endverbatim %} inside the component as cotton makes available snake_case versions of all kebab-cased attributes. (If you use {% verbatim %}{{ attrs }}{% endverbatim %} then the output will already be in the correct case).
  • Shorthand x-bind support (:example). Because single : attribute prefixing is reserved for cotton's dynamic attributes, we can escape the first colon using ::. This will ensure the attribute maintains a single : inside {% verbatim %}{{ attrs }}{% endverbatim %}
